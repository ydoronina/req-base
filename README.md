# ReqBase

Локальная многопроектная база требований с веб-интерфейсом RU/EN, REST API и MCP. BRD и SRS собираются из требований, текстовых разделов, глоссария и схем проекта.

## Запуск через Docker Compose

```powershell
Copy-Item .env.example .env
```

Задайте собственное значение `REQBASE_API_TOKEN` в `.env`. Для демонстрационного проекта добавьте `REQBASE_DEMO=1` перед первым запуском. Откройте [ReqBase](http://127.0.0.1:8000/) после запуска.

```powershell
docker compose up --build -d
```

Compose запускает ReqBase, Kroki и Mermaid companion. Порт приложения привязан к loopback. SQLite, кэш изображений и файлы экспортов находятся в томе `reqbase-data`. Для закрытой сети настройте адрес публикации порта и перечислите имена хостов UI без порта в `REQBASE_UI_HOSTS`. Интерфейс открывается без учётной записи. API и MCP HTTP требуют Bearer-токен.

### Запуск из исходников

Нужны Python 3.12, Node.js 22 (от 22.13), pnpm 11 и системные библиотеки WeasyPrint для PDF.

```powershell
pnpm install --frozen-lockfile
pnpm build
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:REQBASE_API_TOKEN = 'your-token'
$env:KROKI_URL = 'http://127.0.0.1:8001'
.\.venv\Scripts\python.exe -m uvicorn reqbase.api:app --host 127.0.0.1 --port 8000
```

В Linux используйте `.venv/bin/python` и `export` для переменных окружения. `KROKI_URL` относится к уже запущенному экземпляру Kroki. Без него доступны работа с требованиями и локальный предпросмотр Mermaid. PlantUML, серверная валидация, выгрузка схем и документы со схемами используют Kroki.

## Работа с требованиями

- Выберите дерево, плоскую таблицу или канбан. Поиск учитывает код, название, описание, источник, теги и критерии. В дереве предки совпавших строк остаются видимыми.
- Клик по строке открывает карточку. Двойной клик по названию или F2 на строке включает редактирование. Статус и приоритет меняются прямо в ячейке.
- Enter на строке открывает быстрое добавление рядом с ней. В редакторе новой строки Tab делает исходную строку родителем, Shift+Tab поднимает уровень, Enter сохраняет, Esc закрывает редактор.
- Перетащите строку на верхнюю или нижнюю часть другой строки для вставки рядом. Центральная часть строки назначает родителя для FR/NFR. В канбане перетаскивание меняет статус.
- Удаление ветки сохраняет UUID и связи за удалёнными записями. Восстановление доступно в корзине. Из аудит-записи можно вернуть состояние требования до правки.

## REST

- [Swagger UI](http://127.0.0.1:8000/docs) и [OpenAPI](http://127.0.0.1:8000/openapi.json).
- Заголовок `Authorization: Bearer <REQBASE_API_TOKEN>` обязателен. `X-Actor` принимает `user` и `ai:<имя>`. Для REST по умолчанию используется `ai:rest`.
- Для изменения существующего объекта передавайте `expected_version` в JSON. При конфликте сервер возвращает `409` и `current`. Для пакетного PATCH версия указывается для каждого требования. При создании версия необязательна. Для нового проекта передайте `0`, для дочернего требования — версию родителя, для других операций в проекте — версию проекта. `dry_run=true` передаётся в query string.
- Результат изменения требований содержит `items` и `renumbered`. Храните UUID для последующих обращений. `position` — индекс среди соседей с нуля. `depth=0` возвращает корни. При выборе фильтра у строки-предка может быть `matches=false`.
- Для BRD при выборе дочерней ветки включается соответствующее BR, если оно проходит фильтр статусов. Фильтр «Только Approved» использует статус `Approved`. При выборе веток приложение SRS включает активные схемы, связанные с выбранными требованиями и их потомками, которые проходят фильтры статусов. Без выбора веток приложение SRS включает все активные схемы проекта.
- CSV содержит активные требования и иерархию. В колонках `acceptance_criteria` и `tags` хранятся JSON-массивы. JSON-копия сохраняет проект, сущности и историю требований. Скачанные файлы выгрузок находятся в томе. Восстановление отдельного проекта сохраняет UUID, импорт в текущий проект назначает новые UUID и переносит активные связи.
- В Markdown диаграммы встроены как PNG через data URI. Для просмотрщиков с ограничением data URI доступен PDF.

## MCP

**Streamable HTTP.** URL `http://127.0.0.1:8000/mcp`. Передайте `Authorization: Bearer <REQBASE_API_TOKEN>`. При необходимости задайте `X-Actor: ai:codex`.

**stdio с Docker Compose.** В конфигурации клиента укажите абсолютный путь к `compose.yaml`.

```json
{
  "mcpServers": {
    "reqbase": {
      "command": "docker",
      "args": [
        "compose", "-f", "/absolute/path/compose.yaml", "exec", "-T",
        "-e", "REQBASE_MCP_ACTOR=ai:claude", "reqbase",
        "python", "-m", "reqbase.mcp_server"
      ]
    }
  }
}
```

Для запуска без Docker укажите Python из окружения с установленными зависимостями и аргументы `-m reqbase.mcp_server`. Задайте общие с веб-процессом `REQBASE_DATA` и `KROKI_URL`, а также `REQBASE_API_TOKEN` и `REQBASE_MCP_ACTOR` в окружении MCP-клиента. Для stdio доступ определяется запуском локального процесса и его окружением. Описание и схемы аргументов инструментов доступны через `tools/list`.

## Архитектура и проверка

SQLite хранит проект и принадлежащие ему записи как единый агрегат. `BEGIN IMMEDIATE` сериализует конкурентные мутации. Пересчёт кодов, проверка версии и аудит требования выполняются в одной транзакции. FastAPI и официальный Python MCP SDK обращаются к одному сервисному слою. Рендер схем кэшируется на диске по SHA-256 от языка, формата и исходника.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Интеграционный сценарий использует отдельную временную SQLite-базу и проверяет REST, HTTP MCP, аудит, атомарность пакетных изменений, фильтры, резервное копирование и Markdown. Документация компонентов [Python MCP SDK](https://github.com/modelcontextprotocol/python-sdk), [Kroki Compose](https://docs.kroki.io/kroki/setup/use-docker-or-podman/) и [CodeMirror](https://codemirror.net/docs/ref/).
