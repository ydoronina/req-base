# ReqBase и Kroki на этой машине

Рабочая папка — `C:\Users\User\Desktop\Codex\requirements-tool`. ReqBase запущен из исходников на `127.0.0.1:8000`. Для обычного запуска используется `data/reqbase.sqlite3`. Перед записью через MCP проверьте экземпляр и проект: Docker, тестовый запуск с другим `REQBASE_DATA` и запуск из исходников могут обращаться к разным базам. Значения токенов хранятся в окружении или локальном `.env`.

Из корня проекта в PowerShell 7 запустите установленный локальный Kroki:

```powershell
& .\.run\kroki\start.ps1
```

Этот скрипт запускает шлюз Kroki на `127.0.0.1:8001` и компонент Mermaid на `127.0.0.1:8002` в фоне. Повторный вызов при работающих процессах сохраняет их PID. Файлы PID и журналы `gateway.*.log`, `mermaid.*.log` лежат в `.run/kroki/`. Скрипт использует локальные Kroki 0.34.0, Java 21 и PlantUML 1.2026.8, Node из среды Codex и установленный Chrome для Mermaid. Если локальные файлы отсутствуют, используйте вариант с Docker из [README](../../README.md) или восстановите переносимые компоненты по путям в скрипте.

Для перезапуска ReqBase используйте команду Uvicorn из [README](../../README.md) с тем же `REQBASE_DATA`, локальным `.env` и `KROKI_URL=http://127.0.0.1:8001`. На этой машине также использовался Python из среды Codex. Для PDF в этом окружении `WEASYPRINT_DLL_DIRECTORIES` указывает на абсолютный путь к `.run/pdf-engine/onedir/weasyprint/_internal`.

Запрос к `/health` проверяет доступность шлюза. Для проверки рендера отправьте исходник методом POST с `Content-Type: text/plain` на `/mermaid/svg`, `/mermaid/png`, `/plantuml/svg` или `/plantuml/png`. Связь с ReqBase можно проверить запросом POST на `http://127.0.0.1:8000/ui/diagrams/validate` с заголовком `X-ReqBase-UI: 1` и JSON-полями `type`, `source`. Для этого запроса используйте новый исходник, чтобы проверка прошла через Kroki: ReqBase кэширует успешный рендер по типу, исходнику и формату.

Проверка локального запуска дала HTTP 200 и изображения SVG/PNG для блок-схемы Mermaid и диаграммы классов PlantUML. ReqBase вернул `valid: true` для обоих типов. Эта проверка охватывала серверный рендер и валидацию отдельных схем. Сквозная проверка каталога в браузере и выгрузки документов с его схемами описана в [протоколе проверки](verification.md).
